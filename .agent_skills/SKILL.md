# 代码修改硬性规则

修改本仓库 JS/TS 代码时，必须遵守以下规则。优先级：
不改变量名/不删变量/不删注释 > 新增声明默认用 let > 最小改动。
若规则冲突或无法判断，先停下来询问，不要自行猜测或违反。

## 1. 变量声明
- 禁止新增 `var` 声明。
- 已有 `var` 声明保持原样，不要改成 `let` 或 `const`。
- 新增变量声明默认用 `let`。
- 已有 `const` 保持原样，不要改名、不要改声明方式。
- 不要改动已有的变量名。
- 非必要不新增常量，新增常量按“全大写 + 下划线（如 `MAX_RETRY_COUNT`、`DEFAULT_TIMEOUT_MS`）”命名，这不视为改变量名。

## 2. 变量保留
- 不要删除任何已有变量声明，即使它看起来未使用、冗余、调试用或可以合并。
- 如果确实需要删除变量，必须先说明理由并询问，不要直接删。
- 可以修改变量赋值错误，但不要删除变量声明本身。

## 3. 注释
- 不要删除已有注释，包括 TODO/FIXME、文档注释、说明性注释、注释掉的代码。
- 可以修正错误或过时的注释；可以新增注释。
- 格式化代码时不要移除已有注释。

## 4. 修改方式
- 最小改动，只改与当前任务直接相关的代码。
- 不做无关重构、重命名、格式化、清理未使用变量、调整代码风格。
- 不新增 `var`；不随意新增 `const`；不改已有的变量名；不删变量；不删注释。
- 如果 lint/工具要求新增 `const`、删除未使用变量、重命名，先报告冲突并询问。
